Reporting System Final Implementation Summary
1. System Overview

This system accepts a URL from the user,
performs AI-based analysis to determine if it is illegal,
and after user confirmation, generates evidence and report data.
It is a web-based reporting assistant system.

The frontend and server do not communicate directly;
Supabase Realtime Database is used as an event-based communication channel.

2. Technology and Structure

Backend: Python

AI verification: ../src/gemini_classifier.py

Database: Supabase Realtime Database

Storage: Supabase Storage

Server role: State-based task processing worker

Communication method: Database state change detection

3. Data Structure
report_requests table
Column          Description
id              Unique report ID (UUID)
url             URL to be reported
status          Processing status
is_illegal      AI determination of illegality (boolean)
confidence      AI confidence score
reason          Reason for illegal determination (text)
detected_keywords  Detected key keywords
screenshot_url  Screenshot image URL
created_at      Creation timestamp

status values:
submitted
analyzed
confirmed
reported
cancel

4. Overall Processing Flow

The frontend receives a URL and creates a new row in the report_requests table.
The status is set to 'submitted'.

The server detects rows with status 'submitted' and performs AI analysis.

AI analysis results are written back to report_requests and status is changed to 'analyzed'.

The frontend displays the 'analyzed' data to the user.

The user reviews the analysis result, optionally edits the reason, then proceeds to report.

The frontend changes status to 'confirmed' to signal the report request.

The server detects 'confirmed' status and performs a screenshot capture.

The screenshot is uploaded to Supabase Storage and the URL is saved in the report_requests table.

The server changes status to 'reported' to mark all processing as complete.

5. Cancellation

The user can cancel at the 'analyzed' or 'confirmed' stage.

On cancellation, status is changed to 'cancel'.

The server performs no action on rows with 'cancel' status.

'cancel' is a terminal state; no further state changes are allowed.

6. Server Responsibilities
The server only performs the following:

Detect 'submitted' status → run AI analysis

Detect 'confirmed' status → capture and store screenshot

Record results to the database at each stage

The server does NOT:

Communicate directly with the frontend

Render UI

Validate user input

7. Recommended Server Structure

worker.py
  Supabase realtime subscription
  Branch logic based on status

handlers/analyze.py
  Call gemini_classifier
  Write analysis results to database

handlers/screenshot.py
  Capture webpage
  Upload to Storage

8. Frontend Responsibilities

Accept URL input and create report_requests row

Subscribe to database realtime events

Switch screens based on status changes

Display 'analyzed' results

Handle report confirmation and cancellation

9. State Transition Rules

submitted → analyzed or cancel

analyzed → confirmed or cancel

confirmed → reported or cancel

reported → terminal state

cancel → terminal state

10. Implementation Notes

Strictly maintain status-based logic.

The server always checks the current status before performing any action.

Ensure only one task is performed per row at a time.

On failure, explicitly terminate by setting status to 'cancel'.
